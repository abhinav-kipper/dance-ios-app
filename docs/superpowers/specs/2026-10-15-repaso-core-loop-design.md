# Repaso — Sub-project A: Core loop — Design

Date: 2026-10-15
Source brief: `~/Documents/UK_VISA_DOCS/repaso-handoff/HANDOFF.md` (+ `design/*.dc.html` canvases)

## 1. Intent

Repaso turns a camera roll of bachata class videos into a folder library of short clips that play, slow down and loop instantly. It replaces a slow PWA. The core loop is **import → cut → file → practice**, each step under 10 seconds once learned.

**Audience:** the owner plus a few friends via TestFlight (paid Apple Developer account required).

**Decisions made in brainstorming**

| Topic | Decision |
|---|---|
| Distribution | TestFlight, small group. Needs: Photos usage string, app icon, first-launch empty state. No onboarding flow. |
| Minimum OS | **iOS 26 only.** Native Liquid Glass (`glassEffect`), single visual code path. iPhone only, portrait only. |
| PWA data | Start fresh. No migration. |
| Project structure | App target + local Swift package `RepasoCore`, project generated by XcodeGen. No third-party runtime dependencies. |
| Decomposition | Three sub-projects. This spec covers **A** only. |

**Sub-project boundaries**

- **A (this spec):** data model, file storage, import, Home, Folder, Player (core), Cut mode, Move sheet, Clip info sheet, Delete flows.
- **B:** drag-and-drop (reorder folders, drop clips on folders, jiggle, spring-loaded targets), delete from Photos after import, share export, instructor/event tags on import.
- **C:** Player swipe next/previous, frame stepping, pinch-zoom memory, AirPlay, live preview thumbnails, full motion polish, Reduce Motion audit.

The A data model already includes fields used by B/C (`instructors`, `event`, `zoom`, `panX`, `panY`, `recordedAt`) so later sub-projects need no schema migration.

## 2. Success criteria (A)

1. A clip opens and plays with no spinner; tapping the video pauses with no perceptible delay (no double-tap recognizer anywhere).
2. 0.5× sounds slower, not deeper (time-domain pitch correction).
3. Moving a clip to another folder still lists it under its original, with an `In <Folder>` tag.
4. Deleting an original removes it, its file, its thumbnails and all its clips; nothing else is lost.
5. Folder/Home grids scroll smoothly with 200+ clips (poster thumbnails cached on disk, decoded off the main thread).
6. Every interactive element is at least 44×44pt; every icon-only button has an accessibility label.
7. Import of 3 videos shows per-file progress and survives the sheet being hidden.
8. Cut: Mark start → Mark end creates `Clip N` instantly; trim handles enforce a 0.5s minimum.

**Rule of the boundary:** anything with a rule or a number in it (delete semantics, naming, sorting, loop timing, trim clamping, filmstrip window, time formatting) lives in `RepasoCore` and is unit-tested without UI. The app target holds views, `@Observable` view models, and thin AVFoundation/Photos adapters.

**State management:** SwiftData `@Query` for lists; `@Observable` view models for screen state (Player, Cut, Import); `@AppStorage("playbackSpeed")` for the persistent speed. All mutations go through `LibraryService` (a `@MainActor` struct wrapping a `ModelContext`), never ad-hoc `context.delete` in views.

**Navigation:** one `NavigationStack` with a typed path: `enum Route: Hashable { case folder(PersistentIdentifier), unsorted, favorites }`. Player and Cut are `.fullScreenCover`s. Sheets are `.sheet` with `presentationDetents` and the Sheet material as `presentationBackground`.

## 4. Data model (SwiftData)

As in the handoff, with these precise semantics:

```swift
@Model final class Folder {
    @Attribute(.unique) var id: UUID
    var name: String
    var sortIndex: Int
    var createdAt: Date
    var parent: Folder?                                        // nil = root
    @Relationship(deleteRule: .nullify, inverse: \Folder.parent) var children: [Folder] = []
    @Relationship(deleteRule: .nullify, inverse: \Original.folder) var originals: [Original] = []
    @Relationship(deleteRule: .nullify, inverse: \Clip.folder) var looseClips: [Clip] = []
}

@Model final class Original {
    @Attribute(.unique) var id: UUID
    var title: String               // filename without extension at import
    var fileName: String            // "<uuid>.<ext>" in Documents/Videos/
    var importedAt: Date
    var recordedAt: Date?
    var duration: Double
    var instructors: [String] = []  // used in B
    var event: String?              // used in B
    var folder: Folder?             // nil = Unsorted
    var nextClipNumber: Int = 1     // drives "Clip N" naming, never reused
    @Relationship(deleteRule: .cascade, inverse: \Clip.original) var clips: [Clip] = []
}

@Model final class Clip {
    @Attribute(.unique) var id: UUID
    var name: String
    var start: Double
    var end: Double
    var note: String?               // ≤ 140 chars, enforced in LibraryService
    var isFavorite: Bool = false
    var isLearned: Bool = false
    var lastPlayedAt: Date?
    var addedAt: Date
    var sortIndex: Int
    var zoom: Double = 1; var panX: Double = 0; var panY: Double = 0   // used in C
    var original: Original?         // always set; optional only for SwiftData inverse/cascade
    var folder: Folder?             // nil = "lives with its original"
}
```

**Changes vs the handoff, and why**

- `Folder.isSystem` dropped. Unsorted and Favorites are not rows: Unsorted = originals with `folder == nil`; Favorites = clips with `isFavorite`. Avoids special-casing system rows in every query.
- `Clip.folder == nil` means *the clip lives with its original* (it appears only under the original). A clip is "moved" when `folder != nil && folder != original.folder`. Moving a clip back to its original's folder sets `folder = nil`.
- `Original.nextClipNumber` makes `Clip N` names monotonic per original, so deleting Clip 2 never produces a duplicate "Clip 3".
- `Clip.original` is optional at the type level (SwiftData cascade requirement) but `LibraryService` always sets it; queries treat a nil original as corrupt and skip it.

**Where things appear**

| Screen | Shows |
|---|---|
| Folder F, "Originals" | `F.originals`, each with **all** its clips (moved clips carry an `In <X>` tag) |
| Folder F, "Loose clips" | `F.looseClips` where `clip.original.folder != F` (meta: `from <original title>`) |
| Unsorted | originals with `folder == nil`, each with all its clips (same card as in a folder) |
| Favorites | all clips with `isFavorite`, sorted by the active sort |

**Deletion rules (LibraryService)**

- `deleteClip(c)`: removes the bookmark only.
- `deleteOriginal(o)`: deletes video file + its thumbnails, then the model (cascade removes clips wherever they live). UI confirms first with the clip list.
- `deleteFolder(f, mode: .deleteContents)`: recursively deletes subfolders, originals in them (with files), and loose clips in them.
- `deleteFolder(f, mode: .moveContentsUp)`: children folders, originals and loose clips move to `f.parent`, appended after existing items' `sortIndex`. When `f.parent` is nil (root): folders become root folders, originals go to Unsorted, and loose clips get `folder = nil` (they rejoin their original).
- **Normalisation:** after any move, a clip whose `folder` equals its `original.folder` is reset to `folder = nil`. (Example: clip moved to Turns, then its original is also moved to Turns.)
- **Move targets:** for a clip, the Move sheet's root row reads "With its video" (sets `folder = nil`); for an original it reads "Unsorted"; for a folder it reads "Home".
- File deletion happens **after** a successful `context.save()`; a failed file delete is logged, not surfaced (orphan sweep at launch removes unreferenced files in `Videos/`).

## 5. Storage

- **Videos:** `Documents/Videos/<uuid>.<ext>`, `isExcludedFromBackup = false` (user data). Documents is not exposed via Files app in A.
- **Thumbnails:** `Library/Caches/Thumbnails/<id>.jpg` (originals: 30% into the video; clips: 30% into the clip range; 400px max dimension, JPEG 0.8). Cache may be purged by iOS; `ThumbnailStore` regenerates on miss via `AVAssetImageGenerator` on a background task. In-memory `NSCache` of decoded `UIImage`s keyed by id.
- **Orphan sweep** at launch (background): delete files in `Videos/` not referenced by any `Original.fileName`.

## 6. Import

1. `PhotosPicker(selection:, maxSelectionCount: nil, matching: .videos, preferredItemEncoding: .current)` on Home (target: Unsorted) and Folder (target: that folder).
2. `ImportCoordinator` (`@Observable`, app-lifetime) receives `[PhotosPickerItem]` and processes **sequentially** (avoids disk thrash, keeps progress honest):
   - `loadTransferable(type: VideoTransfer.self)` where `VideoTransfer` uses `FileRepresentation(contentType: .movie)` and moves the received file into `Documents/Videos/<uuid>.<ext>`.
   - Read `duration` and `creationDate` (`AVURLAsset.load(.duration, .creationDate)`) → `recordedAt`.
   - Insert `Original` (title = original filename stem or `Video <date>`), generate poster thumbnail, save.
   - Progress per item: `Progress` from `loadTransferable` mapped to a ring; item states `waiting → copying(fraction) → done | failed(message)`.
3. **Import sheet (A scope):** title `Importing N videos` + overall %, rows with poster (once available), name, duration, size, progress ring → green check, failed rows show a rose retry button. Bottom button: `Hide` while copying (import continues; a small glass progress pill shows on Home/Folder), `Done` after. Tag fields and delete-from-Photos card are **B**.
4. Failure (iCloud download failure, disk full): row shows the error; others continue. Partial files are removed.

## 7. Screens

All values (colours, radii, type sizes, spacing) follow handoff §4 exactly; they are centralised in `Theme`. Glass uses `glassEffect(.regular, in: shape)` with `.tint(...)` for green/rose states; `GlassEffectContainer` groups adjacent controls. Sheets use `presentationBackground` with the Sheet recipe.

### 7.1 Home
- Large title **Repaso** (40pt bold, −3% tracking), subtitle `N clips in M folders`.
- Round glass **New folder** button (top right): inserts a card at the top with pop-in and a focused inline name field; empty name on commit → `New folder`.
- Pinned 2-column tiles: **Unsorted** (only when non-empty; `N new` counts originals at root) and **Favorites** (clip count; always shown).
- **Folders** grid (2 col, gap 14): 2×2 poster mosaic (112pt, from up to 4 clips/originals inside, recursively), name, clip count. Empty folders: dashed outline.
- Folder card context menu (A replacement for drag): Rename, Move up/down (reorder), Delete (→ delete-folder sheet).
- Floating white **Import videos** pill (56pt, 38pt from bottom, over a fade to `bg`).
- **Empty state** (first launch, no folders/originals): centred glass card "Import your first class video" + the Import pill.

### 7.2 Folder
- Back `‹ <parent>` + breadcrumb, 34pt title, summary `N clips · M originals · K folders`.
- Chips: **Sort** (menu: Manual, Name, Date added, Recently played; checkmark) and **Hide learned** (toggle, green when on). Sort + hide-learned persist per folder in `@AppStorage` keyed by folder id.
- **Folders** row: subfolders as 3-column cards; `+` card for a new subfolder.
- **Originals:** glass card per original; header = 64×44 poster with duration badge, title, meta `N clips`, green **Cut** pill (opens Cut), chevron expand/collapse (expanded by default; state remembered in memory).
- **Clip rows** (60pt): 46×32 poster, name, duration (mono), `In <Folder>` tag when moved; star toggle (rose), learned circle (green), round play button.
- **Loose clips** section.
- Long-press context menu: Rename/Note (Clip info sheet), Move, Favorite, Mark learned, Delete. (Share = B.) No swipe actions: rows live inside glass cards in a `ScrollView`, and `swipeActions` only works in `List`.
- Floating **Import** pill → imports into this folder.
- Tapping a clip row (or play) opens the Player with the folder's visible clip list (respecting sort + hide learned) as the queue.

### 7.3 Player (core)
- Full-screen black, `AVPlayerLayer` via `UIViewRepresentable`, aspect-fit.
- **Tap video → toggle play/pause immediately** (`onTapGesture` with count 1 only; no competing double-tap). Centre glass circle flash 0.6→1→1.35 fading (0.7s).
- Top glass bar: close (`chevron.down`), centre pill `<Folder> i / n`, trailing slot empty in A (AirPlay = C).
- Bottom floating glass panel (radius 32, 12pt side inset): name (20pt bold), source `<original title> · <recorded date>`, duration (mono), note, 3pt progress line looping, **Speed** segmented control (0.5× / 0.75× / 1×, sliding green pill via `matchedGeometryEffect`), row: **Loop** (default on) · **Pause before repeat** (cycles No pause → 1s → 2s; disabled look when loop off; green countdown ring during the gap) · spacer · Favorite · Learned · (Share = B).
- Chrome idle: after 2.4s playing, top bar fades out and panel dims to 42% (still tappable); any touch restores.
- `isIdleTimerDisabled = true` while presented; restored on dismiss. Sets `lastPlayedAt` on open.
- Audio session `.playback` so it plays with the silent switch on.

**PlaybackEngine (app) + LoopController (core)**
- One `AVPlayer` per Player screen, `automaticallyWaitsToMinimizeStalling = false` (local files), item `audioTimePitchAlgorithm = .timeDomain`, `forwardPlaybackEndTime = clip.end`.
- Open: create item for the original file, `seek(to: start, toleranceBefore: .zero, toleranceAfter: .zero)` then `playImmediately(atRate: speed)`.
- End of range (`AVPlayerItemDidPlayToEndTime`) → `LoopController.didReachEnd()` returns `.restart`, `.restartAfter(seconds)`, or `.stop`. Engine seeks to start and resumes, or shows the gap ring then resumes, or pauses.
- `LoopController` is pure (no AVFoundation), so loop/gap/stop logic is unit-tested.

### 7.4 Cut mode
- Top 430pt: the original playing (tap to play/pause), bottom corners 34. Glass **Done** + title pill.
- Time row: `03:41.2 / 12:48.0` (SF Mono 30pt), `−5s` · play/pause (white circle) · `+5s`. Periodic time observer at 1/20s.
- **Mark button** (60pt, full width): idle green `Mark start`; recording rose `Mark end` with pulsing dot and live length `4.2s`. Second tap creates the clip via `CutSession.mark(at:)` → `LibraryService.addClip` (name `Clip N` from `nextClipNumber`), selects it, flash, toast `Clip N added` (2.2s). If end < start (user scrubbed back), the range is swapped; length < 0.5s is extended to 0.5s (clamped to duration).
- **Filmstrip:** 10 frames sampled across a 40s window (`CutSession.window`): centred on the selected clip, else on the playhead; frozen while dragging. Existing clips as translucent green ranges, recording range rose, selected clip with green trim handles (drag; min length 0.5s; clamp to [0, duration]). Dragging empty strip scrubs (pauses, restores play state on release). Labels: window start/end + hint (`Drag to scrub` / `Drag the handles to trim`). Frames generated with `AVAssetImageGenerator` (tolerance 0.5s) and cached per 40s window in memory.
- **Clips tray:** horizontal 156pt cards, newest first, name (tap selected card's name → inline rename; empty → `Clip`), range `3:21–3:29`, length. Tap selects (and seeks to start); tap selected deselects.
- Trim handle changes are saved to the model on drag end (not per frame).
- Accessibility: trim handles are adjustable elements (±0.1s).

### 7.5 Sheets (A scope)
- **Import** — §6.
- **Move** — "Move clip" (or "Move video" for originals, "Move folder" for folders) folder tree with expand chevrons, 22pt indent per level, root row labelled per §4 "Move targets". Current location marked `Current` and disabled; a folder cannot be moved into itself or its descendants. Selected row: green fill icon + check. Button `Move to <Name>` → success state (green check, `Moved to <Name>`, and for clips `Still listed under its video.`), auto-dismiss after 1.2s. Also shows a 3.8s toast with **Undo** on the presenting screen.
- **Clip info** — Name field, Note field (140 max with counter), **Save** → `Saved` check, dismiss.
- **Delete original** — rose trash icon, `Delete “<title>”?`, `Its N clips will be deleted too.`, preview list, rose `Delete video and N clips`, Cancel.
- **Delete folder** — `Delete “<name>”?` with two actions: `Delete contents` (rose) and `Move contents up`, plus Cancel. Empty folders delete without the choice.
- **Delete clip** — confirmation dialog (system `confirmationDialog`), single rose action.

## 8. Motion (A subset)

Standard spring `.spring(response: 0.45, dampingFraction: 0.7)`; press scale 0.93 (`PressableButtonStyle`); list rows rise 14pt + fade staggered 45ms on first appear; star/learned `symbolEffect(.bounce)`; speed pill `matchedGeometryEffect`; play/pause flash; new tray card springs in from 40pt; sheets standard. All motion respects `accessibilityReduceMotion` (overshoot → plain ease; stagger off; flashes kept as fades). Drag/jiggle/absorb = B.

## 9. Error handling

| Failure | Behaviour |
|---|---|
| Photos permission limited/denied | `PhotosPicker` works without full library access; no special handling in A. |
| Import item fails | Row shows error + retry; partial file removed; others continue. |
| Video file missing at play time | Player shows a glass message "Video file missing" with Delete original action; no crash. |
| Thumbnail generation fails | Neutral glass placeholder with `film` symbol; retried next launch. |
| `context.save()` throws | Logged via `os.Logger`; UI shows a toast "Couldn't save" and rolls back the context. |
| Disk full during import | Item fails with "Not enough space"; remaining items cancelled with the same message. |

## 10. Testing

- **RepasoCore unit tests (Swift Testing, in-memory `ModelContainer`)** — the main safety net:
  - LibraryService: add/rename/move/delete folders; move-into-descendant rejected; delete-contents vs move-up; delete original cascades clips across folders; clip move/back-to-original semantics; `Clip N` naming monotonic; note length cap; favorites/learned toggles; sortIndex append/reorder.
  - Queries: folder contents (originals vs loose clips), Unsorted, Favorites, hide-learned, each sort order, recursive clip counts, mosaic picks.
  - LoopController: loop on/off, gap 0/1/2, gap cancelled by pause/clip change.
  - CutSession: mark start/end, swap when reversed, 0.5s minimum, clamp to duration, trim handles clamp, window centring/clamping at ends, x↔time mapping.
  - TimeFormat: `03:41.2`, `12:48.0`, `0:08`, `3:21`.
  - VideoStore/ThumbnailStore with a temp directory (paths, orphan sweep).
- **App:** `xcodebuild build` for the iOS 26 simulator must pass with zero warnings in our code; one XCUITest smoke test (launch → empty state → create folder → folder appears).
- **Manual acceptance on simulator + one device** against §2, using a few real class videos.
